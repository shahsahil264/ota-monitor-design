Under the Hood

Design + Risks

Design Decisions

3 gates, not 5 (approval fatigue)

UpgradeBlocker stays forever (additive)

ADD label first, REMOVE second (crash-safe)

3-layer idempotency (links + comments + labels)

Stateless runs (Jira IS the database)

Two JQL queries (secondary for fixedIn)

/propose-risk for all YAML (composition)

Always Spike URL (never OCPBUGS)

Stale-button check on every click

Close Spike after PR merge

Corrections via conversation

Human primary, bot safety net

Risks (all addressed)

Fixed Gate fatigue → 3 gates

Fixed Label conflicts → priority ordering

Fixed Slack fragility → best-effort, Jira unaffected

Fixed Button re-posting → "offered" markers

Fixed fixedIn JQL bug → secondary query

Fixed Crash safety → ADD-then-REMOVE

Fixed Phase 5 redundancy → split by action

v2 Version extension after fixedIn

Rollout Early false positives → pause if <90%
